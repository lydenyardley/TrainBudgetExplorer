# The station-page pass, as a replay

`main` carries the finished page. This directory carries how it got there: the
page, build, runner and fixture edits as small patch scripts, the test changes
that answer them, the commit messages, and two drivers that put the whole
sequence back together.

Nothing here runs as part of the build, the tests or the release. There is one
`if __name__ == "__main__"` script in this repo that is a *procedure* rather
than a check, and it is `commit_group.py`.

## Why it exists

The eleven commits from `ede03b6` to `eea30b6` were each built by replaying a
named group of patches onto the commit before it and running the suite. That is
why each commit is reviewable on its own, and why a mid-session normalisation
pass could be thrown away and re-applied rather than hand-repaired at twenty
sites. Keeping the scripts means the sequence can be checked against the
history rather than taken on trust:

    python tools/replay/commit_group.py all tools/replay/messages

That rewrites `7b03c17..HEAD` and is destructive to the working tree. Run it on
a branch you are willing to lose.

## The three ways to run it

| | what it does |
|---|---|
| `python tools/replay/replay.py` | checks the six edited files out at `HEAD` and applies every patch in order, landing the finished state in one pass. No commits. |
| `python tools/replay/commit_group.py <group> <message-file>` | one commit: checks out at `HEAD`, replays that group's patches, stages the files that group touches, commits. |
| `python tools/replay/commit_group.py all <message-dir>` | the nine groups in order, one commit each. |

Run `python tools/replay/commit_group.py` with no arguments to list the groups.

## What is in here

- **`patch.py`** — the patcher every script below uses. Anchors are written as
  they read in a terminal, matched against the file with line endings
  normalised, and written back with the endings the file already had. Each
  anchor must match exactly once: a patch that lands twice is a patch that
  guessed.
- **`normalize.py`** — the four rewrites that repair the escapes a bad pass left
  in `page_templates.py`. Every replay runs this before the first patch.
- **`c1…c13`** — the page, build, runner and fixture edits, one decision each.
  The docstring on each says what was wrong.
- **`t1…t5`, `f1`** — the suite, patched in passes. `t` patches
  `tests/test_build_demo_page.py`, `f1` patches `tests/test_atoc_fares.py`.
- **`tg_*`** — the same test changes cut by test rather than by pass, so a
  commit can land with the tests that cover it. Generated by `split_by_test.py`
  and `two_step.py`, and committed so that a replay does not depend on
  regenerating them. Regenerate with:

      python tools/replay/split_by_test.py
      python tools/replay/two_step.py

  Both read `tests/test_build_demo_page.py` out of git at `BASE` and `FINISHED`
  rather than off disk, so they are safe to run in any worktree.
- **`messages/`** — the eleven commit messages, in the order `commit_group.py
  all` applies them.
- **`failures.py`** — not a driver. It runs the suite and prints one trimmed
  line per failure, because unittest quotes the whole rendered page inside the
  `AssertionError` and twenty string failures is a megabyte of noise.

## The catch

These scripts anchor on the exact text of the files they edit, so they stop
working the moment `page_templates.py` changes for an unrelated reason. They
describe the eleven commits as they were made; they are not a way to make an
edit today. If one fails to apply, that is the scripts ageing, not the page.
