test(browser): the suite follows the page, and says why

The browser suite measures the finished page, so it changes once for the whole
pass rather than once per commit: a check that describes a row's shape cannot
describe a page that is halfway through becoming that row. Everything here is
either a check of the new shape or a check that was measuring the wrong thing
and now measures the right one.

Three of those were wrong before this pass and would have passed on a page with
the defect:

- The railcard control's menu was compared against every card in the payload,
  and the party rule against `card.min` and `card.max` -- fields the payload
  spells `minAdults` and `maxAdults`. Reading an undefined field compared
  undefined to 1, which is false for every card, so the check passed by finding
  nothing to complain about.
- The palette probe opened the first row to measure the fare condition. A
  condition is only printed where a fare carries a restriction code, so on a
  page whose cheapest fare is an unrestricted one the probe measured nothing and
  the check that the condition was measured passed. It now walks the ticket
  modes for a row that has a condition, puts the page back, and fails when a
  page that has one does not measure it.
- The wrap check counted distinct line boxes in a cell and reported two for any
  cell whose only child is an inline span, because the span's line-height sits
  a pixel from the row's strut. A real second line is a whole line lower, so the
  measurement now groups boxes within a few pixels of each other.

The overflow probe names the element that sticks out instead of printing a
pixel count, because a bare number sends whoever reads a red run back to the
stylesheet to guess which element it was. It found the disclosure panel: the
rule that keeps a row's two controls on one line was written for the results
rows and caught the panel too, and a panel is prose.

The rest follows the page: the fare type is a word and the code is in the
record, the shortlist is one select and a strip, the railcard note is in the
row's own panel and there is no drawer, the picker is the field in the heading
and Escape is pressed in it. The picker is the one check that changed shape
rather than wording: the old one pressed the station control a second time to
close the panel, and it timed out, because the control is the field now and is
not on the page to press.
