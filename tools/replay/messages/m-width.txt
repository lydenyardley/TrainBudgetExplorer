fix(page): the table is as wide as its content, and the panel wraps

The table was `width: 100%`, so a row of six columns was spread across a 78rem
page with the station's name in the middle of it. It is as wide as its widest
row now, which is what the reader compares.

The rule that keeps a row's two controls on one line was written for the
results rows and caught the disclosure row too, because a panel is also a last
child. The panel is prose -- a fare sentence, a condition, a feed record -- and
with `white-space: nowrap` inherited, its grid could not wrap: opening any row
at 390px pushed the panel 70px past the edge of the page. The rule now says
which rows it means, by the station they carry.

That one was found by the browser suite's own overflow probe, which names the
element sticking out rather than reporting a pixel count.

Read by running:

  python -m unittest tests.test_build_demo_page -v
  cd tests && node browser_test.cjs ../_demo_site/from/grantham
