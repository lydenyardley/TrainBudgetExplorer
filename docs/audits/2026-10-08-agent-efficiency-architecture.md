# Agent-efficiency architecture review

**Date:** 8 October 2026
**Commit reviewed:** `81ea448` on `main`, with the lane bot's uncommitted edits present in the working tree. Counts and file reads below are taken from `HEAD`, not the working tree, unless a line says otherwise.
**Reviewer:** Grok Bot, first pass on this repository.
**Question:** how cheaply and safely can a coding agent make a correct change here? The agent sees only the files it opens, copies the nearest example, and takes the shortest path that compiles. Which structural changes would cut its token cost and its repeat mistakes?

## Overview

Stack. Python 3 standard library only, with no `requirements.txt` or `pyproject.toml` (measured). Tests use `unittest`. One Playwright suite in Node (`tests/browser_test.cjs`) is fetched with `npx` at run time. CI is one GitHub Actions workflow, `.github/workflows/deploy.yml`, that downloads licensed rail feeds, builds a static site and deploys it to Pages.

## F6. Hot test files are the biggest files in the repo

**Evidence (measured).** `tests/test_build_demo_page.py` was 5,915 lines, 26 classes, 315 test methods, and changed 65 times in 150 commits, the most of any file. `tests/browser_test.cjs` is 6,948 lines and changed 52 times. 27 of the 38 page fixes edited both `page_templates.py` and `tests/test_build_demo_page.py`.

**Why it costs an agent.** Adding a test means opening a 350 KB file to find the nearest example (inferred).

**Level.** Architecture of the test tree.

**Landed (Python half).** The classes that are not the page's own content moved out by feature seam, unchanged: `tests/test_page_runner.py` (1,003 lines), `tests/test_page_caches.py` (793), `tests/test_page_output.py` (702) and `tests/test_page_gates.py` (475). Their shared fixture -- the demo feed, the parsed timetable, the one rendered page and the cache-directory rule -- is `tests/page_harness.py`, so each module still patches the cache directory for the tests it collects. The counts are identical before and after (32 classes, 327 tests, no method renamed), the five modules pass in 185 s between them, and the documented `python -m unittest tests.test_build_demo_page` still runs the page's content tests.

**Still open.** `DemoPageTest` itself is 3,043 lines and 163 methods in one class -- the biggest single item left in this audit, and the one that a reader of the page's prose tests still has to search. `tests/browser_test.cjs` is unsplit as well, and splitting it cannot be verified without running Playwright, which this machine has not done since the review.

**Effort left.** M.

## Quick wins

All five landed on 8 October 2026: `AGENTS.md` and the map test (F2), `tools/replay/` deleted (F3), the fingerprint derived once (F4), `CONTRIBUTING.md` fixed (F2), and `tests/test_atoc_fares.py` profiled with the fixture shared (F5).

## Not worth doing

- Moving the 22 root modules into a package. High import and CI churn, and an `AGENTS.md` map gets most of the orientation benefit (guess).
- Adding a Python type checker for page defects. The defects live in JavaScript files, which Python types do not reach; `node --check` catches the syntax half of it (inferred).
- Splitting `atoc_fares.py`. It is 4,740 lines but changed 19 times in 150 commits, a third of the page's rate (measured).
- Checking in real feed samples as fixtures. The data is licensed (ADR-0005).
